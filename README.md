# 局域网聊天室 (wifichat)

一个开箱即用的**局域网浏览器聊天工具**：局域网内任何人打开一个链接就能在浏览器里互相聊天，无需注册、无需安装客户端、不依赖任何外部服务器，所有消息都保存在本地。

打包后是一个**单文件 exe**，复制到任意 Windows 电脑双击即可使用——启动时它会自动探测局域网内是否已有聊天服务：有就直接加入，没有就把自己变成服务器。

---

## 功能特性

### 聊天
- **零安装使用**：把 `http://主机IP:3000` 发给局域网内的人，用浏览器打开即聊
- **实时收发**：基于 WebSocket 推送，断线自动重连
- **IP 自动识身份**：以访问者 IP 作为身份，无需注册登录
- **昵称只需设一次**：服务端按 IP 记住昵称，浏览器也有本地备份，之后不再询问，随时可改
- **离线留言**：消息全部持久化，重新打开页面会看到完整历史，并用「以下是你不在线时的留言」分隔线标出你离开期间的新消息

### 消息提醒
- **@提醒**：输入 `@` 自动弹出用户列表补全（支持方向键/回车），也可点击在线用户直接 @，或 `@所有人`
  - 被 @ 的人会收到：消息高亮 + 「@我」角标、提示音、标签页标题闪烁「⚠ 有人 @ 你」、Windows 系统通知、手机震动
  - @标记随消息一起保存，离线期间被 @ 的人下次打开依然能看到高亮
- **未读提醒**：标签页标题显示未读数 `(3) 局域网聊天室`，网页图标（favicon）显示红点数字角标，页面在后台时弹出系统通知
- 回到页面即自动清空所有提醒

### 发送内容
| 类型 | 支持方式 | 大小限制 |
|---|---|---|
| 图片 | 🖼 按钮选择、拖入窗口、`Ctrl+V` 粘贴截图 | 10 MB |
| 视频 | 🎬 按钮选择、拖入窗口、`Ctrl+V` 粘贴（内嵌播放，带上传进度） | 200 MB |
| 表情 | 😀 面板内置 150+ emoji，点击插入输入框 | — |
| 贴纸 | 共享贴纸库，支持图片和视频贴纸（视频贴纸静音循环播放） | 图片 5 MB / 视频 200 MB |

- **一键收藏贴纸**：鼠标悬停在聊天中的任意图片或视频上，点「存为贴纸」即可复制进共享贴纸库，局域网内所有人立刻可用
- 贴纸使用 `＋` 也可以直接上传（GIF 动图、短视频均可）

### 界面
- **白天 / 黑夜主题**：一键切换，浏览器记住选择，加载前应用避免白屏闪烁
- **在线用户列表**：右侧实时显示当前在线成员，可收起/展开并记住状态
- **设置面板**：点击右上角昵称打开，可修改昵称、切换主题、清空全部聊天记录（贴纸库保留，所有在线用户同步清空）
- 自适应手机浏览器；手机小屏自动隐藏侧边栏

## 快速开始

### 方式一：源码运行（需要 Node.js 18+）

```bash
npm install
npm start
```

启动后控制台会打印访问地址：

```
本机访问:   http://localhost:3000
局域网访问: http://192.168.1.4:3000   <== 把这个链接发给局域网内的同事/朋友
```

Windows 下也可以直接双击 `启动聊天室.bat`。

### 方式二：使用打包好的 exe（目标电脑无需安装 Node）

```bash
npm install
npm run build          # 等价于 node build.js，产物：dist/localchat.exe
```

- **便携版**：`dist/localchat.exe` 放到任意位置双击即用
- **安装包**：把文件改名为含 `setup` 的任意名字（如 `LocalChat-Setup.exe`）再双击，即进入安装模式

安装模式会：复制程序到 `%LOCALAPPDATA%\LocalChat\`、创建桌面和开始菜单快捷方式、添加防火墙放行规则（会弹一次 UAC 授权）、写入卸载脚本。

### exe 的启动逻辑

```
双击图标
   ├─ 本机已在运行？ ────────────→ 直接打开浏览器加入
   ├─ UDP 广播探测局域网 ──有服务─→ 直接打开浏览器加入（本程序随即退出）
   └─ 探测无结果 ────────────────→ 本机启动服务，打开聊天框，持续应答他人探测
```

探测协议：向局域网广播地址的 UDP `37441` 端口发送 `LOCALCHAT_PING`，运行中的服务应答 `LOCALCHAT_PONG:<端口>`，探测方再用 `GET /api/me` 校验确认。因此**同一局域网只需一台机器当主机，其他人启动 exe 只会加入，不会重复起服务**。

## 项目结构

```
localchat/
├── server.js            服务端：HTTP 静态服务 + WebSocket 推送 + REST 接口 + 本地存储 + UDP 发现应答
├── launcher.js          exe 入口：局域网探测 → 加入或启动服务；文件名含 setup 时执行自安装
├── build.js             打包脚本：内嵌前端资源 → esbuild 打包 → Node SEA 生成单文件 exe
├── public/
│   └── index.html       完整前端（样式与脚本内嵌，无框架、无构建步骤）
├── package.json
├── 启动聊天室.bat        开发期一键启动
└── data/                运行时数据（已 gitignore）
```

## 数据存储

聊天数据全部保存在**当前主机**本地，不经过任何外部服务：

| 运行方式 | 数据目录 |
|---|---|
| 源码运行 | 项目目录下 `data/` |
| exe 运行 | `%LOCALAPPDATA%\LocalChat\data\` |

```
data/
├── messages.jsonl   消息记录，每行一条 JSON（最多保留 5000 条，超出自动裁剪）
├── users.json       IP → 昵称映射
├── uploads/         聊天中发送的图片和视频
└── stickers/        共享贴纸库
```

> 注意：聊天记录属于主机本地数据。换一台电脑当主机后，新主机的历史记录是从头开始的。

## 接口一览

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/` | 聊天页面 |
| GET | `/api/me` | 当前访问者身份（IP + 昵称） |
| POST | `/api/nickname` | 设置昵称 |
| POST | `/api/upload?name=<文件名>` | 上传图片/视频（请求体为二进制），按扩展名白名单校验 |
| GET / POST | `/api/stickers` | 列出贴纸 / 上传贴纸 |
| POST | `/api/save-sticker` | 把聊天中的图片或视频收藏为贴纸 |
| POST | `/api/clear` | 清空全部聊天记录（消息与已上传媒体） |
| GET | `/uploads/*`、`/stickers/*` | 媒体文件 |
| WS | `/ws` | 实时消息通道（`chat` / `image` / `video` / `sticker` / 系统消息） |

服务端会校验上传文件的扩展名白名单（`png/jpg/jpeg/gif/webp` 与 `mp4/webm/mov/m4v`）、限制大小，并拒绝对贴纸目录以外的路径收藏，避免路径穿越。

## 常见问题

**局域网里其他电脑打不开？**

按以下顺序排查：

1. **先 ping 得通，端口不通** —— 基本都是 Windows 防火墙。注意：**阻止规则优先级高于放行规则**，如果之前弹「是否允许通过防火墙」时被拒绝或被误关，系统会留下一条隐藏的阻止规则，此时任何放行规则都无效。用管理员 PowerShell 检查并删除：
   ```powershell
   Get-NetFirewallRule -DisplayName "Node.js JavaScript Runtime" | Where-Object { $_.Action -eq 'Block' } | Remove-NetFirewallRule
   ```
   使用安装包安装时会自动添加放行规则，可避免此问题。
2. **第三方安全软件** —— 腾讯电脑管家等会装网络过滤驱动，绕过 Windows 防火墙单独拦截，需要在其中放行该程序。
3. **ping 完全不通** —— 检查两台机器是否在同一网段（如都是 `192.168.1.x`）。
4. **手机打不开** —— 部分路由器默认开启「AP 隔离」，禁止无线设备互访，需在路由器后台关闭。

**端口 3000 被占用？**

同一台机器只能有一个主机实例。重复启动 exe 会自动检测并加入已有服务，不会冲突。源码运行可通过环境变量换端口：`set PORT=8080 && npm start`。

**exe 探不到另一台机器上的服务？**

确认对方程序仍在运行（主机窗口没有关闭），并且两台机器在同一局域网、UDP 37441 未被防火墙拦截。

## 技术栈

- **服务端**：Node.js 原生 `http` / `dgram`，无 Web 框架；消息通道使用 [`ws`](https://github.com/websockets/ws)
- **前端**：单文件原生 HTML/CSS/JS，无框架、无构建
- **打包**：esbuild 打包 + Node.js SEA（Single Executable Application），前端资源内嵌进 exe
- **存储**：纯文件（JSONL + 目录），无数据库、无外部依赖
